# Family OS — Итерация 4.2: авторизация (запомненные устройства, профиль, управление участниками)

## 1. Запомненные устройства

- При входе с кодом 2FA отметка «Запомнить это устройство на 30 дней»
  (включена по умолчанию). Браузер получает случайный токен (32 байта),
  сервер хранит только sha256 (`trusted_devices.tokenHash`).
- Следующий вход: **пароль нужен всегда**, код 2FA не спрашивается, если
  токен действителен, не отозван, не истёк и IP уже знаком этому
  устройству (`TRUSTED_DEVICE_IP_POLICY=strict`, по умолчанию).
- Новый IP (например, дома по LAN 192.168.x, вне дома через Tailscale 100.x)
  → один раз спросит код, после этого IP запоминается за устройством
  (до 10 адресов).
- **MAC-адрес не используется**: браузер его не передаёт, через Tailscale и
  Docker он до сервера не доходит. IP в Tailscale закреплён за устройством
  ключом WireGuard — надёжный второй признак.
- Токен устройства хранится в браузере отдельно для каждого email и не
  удаляется при «Выйти».
- Отзыв: «Мой профиль → Запомненные устройства → Забыть», у владельца — в
  карточке участника. Автоматически отзываются при смене/сбросе пароля,
  отключении/сбросе 2FA, приостановке участника. Удаления нет — у записи
  ставится `revokedAt` и причина.

`.env` (необязательно):
```
TRUSTED_DEVICE_IP_POLICY=strict   # off — не проверять IP
TRUSTED_DEVICE_DAYS=30
```

### Реальный IP клиента (важное исправление)
Встроенный прокси Next.js не передавал в API `X-Forwarded-For`: в журнале
входов был IP контейнера web, а подделанный клиентом заголовок проходил
насквозь. Теперь web запускается через `apps/web/server.js` (Dockerfile:
`CMD ["node", "server.js"]`), который **перезаписывает** `X-Forwarded-For`
реальным адресом сокета. API принимает заголовок только от частной сети
(контейнер web). Проверка после деплоя: «Мой профиль → Активные сеансы» —
у текущего сеанса должен быть ваш IP (100.x или 192.168.x), а не 172.x.
Если видно 172.x — в `/etc/docker/daemon.json` нужно `"userland-proxy": false`
и перезапуск docker.

## 2. Мой профиль (`/profile`, ссылка в боковом меню)
Смена пароля (нужен текущий; остальные сеансы завершаются, устройства
сбрасываются), смена email (нужен пароль), 2FA: новые резервные коды,
отключение/перенастройка (с паролем), активные сеансы («этот сеанс»,
завершить остальные), запомненные устройства.

## 3. Карточка участника (`/members/<id>` — клик по имени в «Участниках»)
Только **владелец** (другой владелец — недоступен; над собой — через профиль):
- ФИО и email для входа (проверка формата и занятости);
- новый пароль, если участник забыл (все его сеансы и устройства — отзыв);
- 2FA: «Сбросить» (сменил телефон — при входе настроит заново) или
  «Включить вместе с участником» — QR на экране владельца, участник
  сканирует и называет код;
- активные сеансы (завершить все), запомненные устройства (забыть),
  журнал входов (успешные и неудачные попытки, IP, устройство).
Партнёр видит участников, но не управляет учётными записями.

## 4. Безопасность — что исправлено попутно
- `POST /auth/2fa/setup` при уже включённой 2FA молча её выключал — любая
  сессия могла снять 2FA без пароля. Теперь отказ; перенастройка — через
  отключение с паролем.
- В access-токене теперь id сессии: отзыв сеанса и приостановка действуют
  сразу, а не через 15 минут. `refresh` не продлевает сессию неактивного
  пользователя.
- «Выйти» отзывает сессию на сервере (раньше только чистился браузер).
- Сессии сохраняют устройство и IP (поля были, но не заполнялись).

## Попутно (бот и счета)
- Бот: `/ask … баланс … семейный счёт альфа` отвечает точным балансом из
  карточки счёта, без ИИ. Суммы с копейками (378,45 ₽) — раньше округлялись.
- ИИ получает числа готовыми русскими строками («378,45»): модель прочитала
  JSON-число 378.45 как «378 450 ₽». В данные для вопросов добавлены балансы
  счетов.
- Формы: «Данные не прошли проверку» теперь с перечнем полей; у нового счёта
  валюта RUB и тип «Расчётный» по умолчанию.
