## Критические ошибки

Найдены и устранены в процессе развёртывания (все — до финального прогона 15/15):

1. **`SearchHit` не экспортирован** — блокировало сборку backend (`tsc` ошибка TS4053). Исправлено: добавлен `export` к интерфейсу.
2. **Отсутствовал `rootDir` в `tsconfig.build.json`** — Prisma/Nest собирались в `dist/src/main.js` вместо `dist/main.js`, контейнер `api` падал в рестарт-луп (`Cannot find module '/app/dist/main.js'`). Исправлено: явно задан `rootDir: "./src"`.
3. **`NEXT_PUBLIC_API_URL` не передавался как build-time `ARG`** — фронтенд компилировался с зашитым `localhost:3001` вместо `api:3001`, все запросы к API из браузера падали `ECONNREFUSED`/500. Исправлено: добавлен `ARG`/`ENV` в `Dockerfile` web и `args` в `docker-compose.yml`.
4. **`AuditController` не был защищён `@UseGuards(JwtAuthGuard)`** — эндпоинт `/audit-log` падал с 500 (`Argument userId is missing` в Prisma) вместо корректных 401/403 для любого запроса, включая легитимные. Не было утечки данных (данные никому не отдавались), но контроль доступа фактически не работал. Исправлено: добавлен guard.

На момент приёмки все четыре пункта закрыты и повторно подтверждены автоматическим прогоном.

## Известные ограничения

- **HTTPS не настроен.** По решению, принятому в переписке с владельцем системы: Family OS работает по HTTP и доступен только из локальной сети (`192.168.1.18:3400`), по аналогии с уже существующими на этом сервере AdGuard (`:3000`) и Grafana (`:3300`), которые тоже без TLS. Это осознанное отступление от пункта 1.2/15 мастер-чек-листа, а не упущение — трафик не покидает LAN. При появлении внешнего доступа (не LAN-only) это нужно будет пересмотреть в первую очередь.
- Адаптивность проверялась только в Safari на macOS (desktop) — реальные телефон/планшет (iPhone Safari, Android Chrome, портретная/альбomная ориентация) в этом цикле не проверялись глазами на устройстве.
- Firefox/Chrome desktop отдельно не проверялись (использовался Safari).
- Загрузка файлов (PDF/JPG/PNG, лимиты размера, проверка MIME-типа) не проверялась вручную в этом цикле — модуль реализован и покрыт кодом, но не тестовым сценарием.
- Раздел «Единый интерфейс сущностей» (список/карточка/поиск/фильтрация/сортировка) проверен частично — есть список, карточка, создание, редактирование, история; фильтрация и сортировка в UI базы знаний не реализованы (только через API-параметры).
- SSH root-доступ не проверялся — по прямому указанию владельца системы, вне объёма этой приёмки.
- Очередь фоновых задач и кэш не используются в Итерации 1 (архитектурно не требовались) — неприменимо, не проверялось.

## Проверка безопасности

**PASS** (в границах того, что проверялось — см. ограничения выше)

- `.env`, `docker-compose.yml` недоступны через web (404).
- `passwordHash` не возвращается в ответах API.
- Секреты (`TWO_FACTOR_ENC_KEY`) не светятся в `docker compose logs`.
- Неавторизованные запросы отклоняются (401), поддельный JWT отклоняется (401), неверный пароль отклоняется (401).
- IDOR-проверка: чужая сущность недоступна ни по чужому `X-Family-Space-Id` (403), ни по прямому id через свой легитимный space (404).
- Пароли хранятся только как argon2-хэши.
- 2FA обязательна, секрет шифруется перед хранением в БД.

Не проверялось отдельно в этом цикле: CSRF-защита, XSS-инъекции в пользовательском вводе (markdown/заголовки), SQL-инъекции (архитектурно маловероятны — используется Prisma с параметризованными запросами, но целевого пентеста не проводилось), ограничение типов/размера загружаемых файлов.
