# Family OS — Итерация 4: финансы семьи + ИИ

Запрос: доработать финансовый учёт под семью (общий котёл, без «кто кому
должен»), взять лучшее из Firefly III 6.7.9, Maybe 0.6.0, PariPari 0.4 и
Spliit, подключить ИИ (в том числе локальный на ноутбуке) — особенно к
отчётности; дать способ убрать тестовые операции.

## Что взято из референсов

| Откуда | Что | Как у нас |
|---|---|---|
| Firefly III (rules), Maybe (rules engine) | Правила «условие → действие» | `finance_rule`, страница `/finance/rules`; при импорте и к старым операциям (с предпросмотром) |
| Maybe (recurring), Firefly III (bills) | Поиск подписок и регулярных платежей, статус «оплачено/ожидается» | `/finance/recurring`, чистая логика `recurring-detection.ts` |
| Firefly III (piggy banks), PariPari (goals timeline) | Копилки с пополнениями и прогнозом даты | `/finance/goals`, `goal-progress.ts`, тип `financial_goal_contribution` |
| Spliit | Взаиморасчёты между участниками | **Сознательно не взято** — по решению владельца: семья = общий котёл |
| PariPari | Правило деления 50/50 / по доходам, взносы | **Не взято** по той же причине |

## ИИ

**Принцип:** все цифры считает код (`finance-report-facts.ts → buildReportFacts`),
модель получает компактный JSON фактов и только пишет текст. После ответа
`findUnverifiedNumbers` ищет в тексте числа, которых нет в фактах, — такой
отчёт помечается предупреждением. Если модель недоступна, отчёт всё равно
формируется по шаблону (`buildFallbackNarrative`).

- **ИИ-отчёт** (`/finance/reports`): доходы, расходы, итог, норма сбережений,
  категории против прошлого периода и среднего за 3 периода, аномалии,
  крупные траты, бюджеты, обязательные платежи, копилки, Net Worth.
  Генерация в фоне — запись `finance_report` со статусом GENERATING,
  страница опрашивает каждые 4 с. Отчёты не удаляются, только архив.
  Выгрузка: Markdown и печать → PDF.
- **Вопрос ИИ про финансы** за выбранный период.
- **ИИ-подсказки категорий** для операций без категории — только из вашего
  справочника, применяются после подтверждения, из подсказки можно
  сделать правило.

### Цепочка моделей ПК → ноутбук

Раньше резервный адрес обязан был быть того же типа, что и основной.
Теперь у резервного свой тип API и модель:

```bash
# .env на сервере
LLM_PROVIDER=openai_compatible
LLM_URL=http://100.71.172.64:1234          # LM Studio на ПК
LLM_MODEL=qwen/qwen3.6-35b-a3b
LLM_FALLBACK_URL=http://host.docker.internal:11434   # Ollama на этом ноутбуке
LLM_FALLBACK_PROVIDER=ollama
LLM_FALLBACK_MODEL=qwen3:8b
LLM_REPORT_TIMEOUT_MS=300000               # отчёт на CPU — до 5 минут
```

Ollama на ноутбуке должна слушать `0.0.0.0` (systemd override
`OLLAMA_HOST=0.0.0.0`), иначе из контейнера она недоступна. Статус каждой
модели — на странице «ИИ-отчёты» (кнопка «Проверить»).

Блоки `<think>…</think>` (Qwen3 через LM Studio) вырезаются из ответа.

Next.js по умолчанию обрывает проксируемый `/api`-запрос через 30 с —
поднято до 5 минут (`experimental.proxyTimeout` в `next.config.mjs`).

## Очистка тестовых операций

1. **В интерфейсе** — «Транзакции → Очистка тестовых» (`/finance/cleanup`):
   фильтр (все / счёт / источник / даты) → предпросмотр → ввод количества
   → архив. Обратимо. Архивные операции не попадают в аналитику, бюджеты,
   отчёты.
2. **Исправлено:** ключ дедупликации импорта, указывающий на архивную
   операцию, больше не считается дублем — ту же выписку можно импортировать
   заново, ключ перенаправляется на новую операцию.
3. **Физическое удаление** (исключение из правила «удаления нет», только для
   тестового мусора) — `ops/purge-test-finance.sh`: сухой прогон по
   умолчанию, `--execute` делает `pg_dump` в `backups/`, просит ввести
   «УДАЛИТЬ», удаляет операции вместе с версиями/связями/ключами
   дедупликации в одной транзакции, пишет запись в аудит. Счета, категории,
   бюджеты не трогает. Проверен на PostgreSQL 16 с реальными миграциями.

## База данных

Миграций нет — новые типы (`finance_rule`, `finance_report`,
`financial_goal_contribution`) и новые поля (`financial_goal`:
startAmount/trackingMode/savingsAccountId/icon; `financial_need`:
dueDay/matchPattern/recurringPeriod/isSubscription/notes) — в общей
таблице `entities` через реестр типов. Условия правил
(`attributes.conditions`) и факты отчёта (`attributes.facts`) — JSON вне
схемы полей, как `periodAllocations` у бюджета.

## Права и журнал

- Все чтения — `FINANCE:VIEW`; применение правил/подсказок — `FINANCE:EDIT`;
  очистка — `FINANCE:ARCHIVE`; создание отчётов/правил/пополнений —
  `FINANCE:CREATE`.
- Все изменения идут через `EntitiesService` → версия записи + аудит.
  Дополнительно в аудит: `finance.rules_applied`, `finance.cleanup_archived`,
  `finance.report_generated` (модель и время), `finance.ai_question`,
  `finance.ai_categories_applied`, `finance.purge_test_transactions`.
