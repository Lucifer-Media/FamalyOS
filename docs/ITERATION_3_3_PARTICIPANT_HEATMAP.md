# Family OS — Итерация 3.3 (аналитика по участникам, тепловая карта расходов)

Продолжение Итераций 3-3.2. Закрывает два пункта из списка «Расширенная
аналитика»: *«Аналитика по участникам и счетам»* и *«Тренды, прогнозы и
heatmap расходов»* (heatmap — сделано; тренды/прогнозы по счетам уже были
в дашборде с Итерации 1-2).

## Что сделано

### Владелец счёта — новое, до этого нигде не использовалось
Обнаружилось, что `Entity.ownerPersonId` (общее поле, есть у любой записи
с Итерации 1) нигде не заполнялось для счетов — интерфейс никогда не
предлагал выбрать владельца. Без этого "аналитика по участникам" была бы
пустой (некого агрегировать). Добавлено:
- Новый переиспользуемый компонент `PersonSelect`
  (`components/ui/person-select.tsx`) — выпадающий список участников семьи
  (`GET /people`, уже существующий, ранее не использовался фронтендом
  Финансов).
- Поле «Владелец счёта» на создании счёта (`/finance`) и в карточке
  редактирования реквизитов (`/finance/accounts/[id]`).
- Бейдж с именем владельца на карточке счёта в списке.

### Аналитика по участникам
`FinanceAnalyticsService.getAnalyticsByParticipant` — операция считается
принадлежащей участнику через счёт, на котором она произошла
(`transaction.accountId → account.ownerPersonId → Person.fullName`).
Операции по счетам без владельца группируются как «Без владельца счёта» —
не теряются и не падают. Плановые операции по-прежнему исключены из факта
(тот же `isActualTransaction`, что и везде). Новый эндпоинт:
`GET /finance/analytics/by-participant?startDate&endDate`.

### Тепловая карта расходов
`FinanceAnalyticsService.getSpendingHeatmap` — сумма расходов по каждому
дню периода (возвращает **все** дни диапазона, включая нулевые — чтобы
сетка на фронте была без дыр). Эндпоинт: `GET
/finance/analytics/heatmap?startDate&endDate`.

На фронтенде — `/finance/analytics`, компонент `SpendingHeatmap`:
сетка недель/дней (как GitHub-граф вкладов), интенсивность цвета от суммы
трат в конкретный день относительно максимума за период, легенда
«меньше→больше». Реализовано вручную (SVG/CSS-сетка), без подключения
новой библиотеки визуализации — вписывается в существующий набор
зависимостей проекта.

## Тесты
9 новых тестов (`finance-analytics-participant-heatmap.spec.ts`):
группировка по владельцу, обработка счетов без владельца, исключение
плановых операций из обоих новых отчётов, полнота диапазона дней в
heatmap (включая нулевые), исключение доходов из heatmap (это карта
именно расходов). Итого backend: **160/160** тестов проходят (было 155).
