# Family OS — Итерация 3.2 (раздел «Портфель»: кредиты, инвестиции, долги, Net Worth)

Продолжение Итераций 3 и 3.1. Закрывает последний крупный пробел до
famfi.app-паритета из списка пользователя:

> Кредиты, займы, ипотека / Вклады и инвестиции / Сравнение кредитных
> предложений / Net Worth семьи в реальном времени / график платежей,
> симуляция досрочного погашения и расчёт выгоды от рефинансирования.

## Что сделано

### Новые типы сущностей (без миграций — обычные Entity + attributes)
- `loan_account` — кредит/заём/ипотека: кредитор, тип, сумма, остаток,
  ставка, срок, счёт списания.
- `investment_account` — вклад/инвестиция: тип, вложено/текущая стоимость,
  ожидаемая доходность, даты.
- `debt` — долг (кто должен вам / кому должны вы): контрагент, направление,
  суммы, срок.

Все три — обычные типы в общем реестре, поэтому автоматически получили
архивирование, редактирование, версии, права доступа и журналирование —
никакого отдельного кода для этого писать не пришлось (тот же генеральный
механизм, что и в Итерации 3 для счетов/бюджетов).

### Расчёты — чистая логика, тестируется в изоляции
`apps/api/src/finance/loan-calculations.ts` (без Prisma-зависимостей, как
`budget-periods.ts`):
- `buildAmortizationSchedule` — аннуитетный график платежей от текущего
  остатка кредита. Последний платёж явно закрывает остаток в ноль (не
  копит хвост от округлений).
- `simulateEarlyRepayment` — симуляция единоразового досрочного платежа в
  двух режимах: «сократить срок» / «сократить платёж», с расчётом
  сэкономленных процентов.
- `compareRefinancing` — сравнение текущего кредита с гипотетическим новым
  (ставка/срок/комиссия за переоформление) — показывает, выгодно ли
  рефинансирование и на сколько.
- `forecastInvestment` — прогноз стоимости вклада/инвестиции по сложным
  процентам, три сценария (базовый ±5 п.п.).

14 юнит-тестов (`__tests__/loan-calculations.spec.ts`), включая проверку
корректности классической формулы аннуитета, отсутствия "зависшего"
остатка в конце графика, экономии при досрочном погашении в обоих режимах,
знака экономии при выгодном/невыгодном рефинансировании.

### Net Worth в реальном времени
`PortfolioService.getNetWorth` (`portfolio.service.ts`, 7 юнит-тестов):
наличные на счетах + стоимость вкладов/инвестиций + то, что вам должны −
остаток по кредитам − то, что должны вы = Net Worth. Считается на лету по
актуальным данным (не кэшируется), в коде — не моделью.

### Новые эндпоинты
- `GET /finance/portfolio/net-worth`
- `GET /finance/portfolio/loans/:id/schedule`
- `POST /finance/portfolio/loans/:id/simulate-early-repayment`
- `POST /finance/portfolio/loans/:id/compare-refinance`

### Новые страницы
- `/finance/portfolio` — сводка Net Worth, список кредитов, список
  вкладов/инвестиций (с мгновенным прогнозом на 1/3/5/10 лет по трём
  сценариям, без похода на сервер), учёт долгов с быстрой фиксацией
  частичного/полного погашения.
- `/finance/portfolio/loans/[id]` — редактирование кредита (тот же
  generic-паттерн: DynamicEntityForm + архив + версии), таблица графика
  платежей, калькулятор досрочного погашения, калькулятор сравнения
  рефинансирования — с реальными числами по конкретному кредиту.
- «Портфель» добавлен в общую суб-навигацию `FinanceSubNav`.

### Мелкие пункты из списка пользователя, закрытые попутно
- **Бюджетирование / предупреждение о приближении к лимиту**: на
  `/finance/budgets` теперь показывается бейдж «Приближается к лимиту»,
  когда факт достиг `alertThresholdPercent` бюджета, и «Лимit превышен» —
  когда факт ≥ 100%. Поле `alertThresholdPercent` уже существовало в схеме
  с Итерации 1-2, просто не было подключено к интерфейсу.
- **Экспорт в CSV**: кнопка на `/finance/transactions` выгружает
  отфильтрованный список операций в CSV (Excel/PDF — см. ниже, отдельная
  задача).

## Что осознанно НЕ сделано в этой итерации (честно)

- **Мгновенная запись через Telegram-бота.** У Family OS сейчас вообще нет
  бот-интеграции — ни кода, ни токена, ни вебхука. API слушает только
  `127.0.0.1`, наружу не торчит. Это отдельная инфраструктурная задача
  (см. `TECH_DEBT.md`, пункт 38), не «доделка».
- **Аналитика по участникам, heatmap, экспорт в Excel/PDF.** По счетам
  аналитика уже реализована ранее; по участникам — нужно новое
  агрегирование через `ownerPersonId` счёта; heatmap и Excel/PDF — отдельная
  работа (пункт 39).
- **Сводная статистика переводов между счетами** — сами переводы видны как
  обычные операции, отдельного отчёта «сколько денег перетекло между
  своими счетами» нет (пункт 40).
