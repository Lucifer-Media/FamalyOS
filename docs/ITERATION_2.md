# Family OS — Итерация 2 (документы, активы, локации, медицина, аккаунты, OCR)

## Что добавлено

- **Реестр специализированных типов** (`apps/api/src/entity-types/entity-type-registry.ts`) —
  единый источник правды для 27 типов сущностей (документы личности, активы, локации,
  медицина, лекарства, аптечки, аккаунты). Отдаётся фронтенду через `GET /entity-types`,
  формы строятся динамически — не нужно писать отдельный React-компонент под каждый тип.
- **Валидация атрибутов** по этому реестру при создании/изменении сущности
  (`validateEntityAttributes`) — включая явную защиту от хранения паролей в карточках.
- **Иерархия сущностей** (`Entity.parentEntityId`) — используется деревом локаций
  (Страна → Город → Дом → Квартира → Комната) и вложенными записями паспорта
  (регистрации/браки/дети).
- **Паспорт РФ** — первая полностью специализированная карточка с вложенными сущностями,
  отдельные эндпоинты `/documents/passport-rf`.
- **OCR-конвейер** (Tesseract, локально): загрузка → извлечение текста → эвристическая
  классификация типа → предзаполнение формы → **обязательное подтверждение пользователем**
  (`DocumentIntake`). Реальная карточка не создаётся, пока пользователь не подтвердит.
- **Отчёт «скоро истекает срок годности»** для аптечек (`GET /first-aid-kits/expiring`).

## Известные ограничения (честно, как и в Итерации 1)

1. **OCR сканированных PDF не реализован.** Работает: PDF со встроенным текстовым слоем
   (обычный экспорт из Word/госуслуг) и изображения (JPG/PNG) — для них Tesseract
   действительно распознаёт текст. Скан документа, сохранённый как PDF-картинка без
   текстового слоя, пока не обрабатывается — нужна растеризация страниц (poppler-utils),
   что усложняет Docker-образ. Обходной путь: сфотографировать документ и загрузить как JPG.
2. **Tesseract.js скачивает языковые данные (`rus.traineddata`, `eng.traineddata`, несколько
   МБ) при первом реальном запросе OCR** — контейнеру `api` нужен исходящий доступ в интернет
   при первом использовании функции загрузки документа. Данные кэшируются в volume
   `family_os_tesseract_cache` и повторно не скачиваются. Если хотите работать полностью
   офлайн — нужно предзагрузить `.traineddata` файлы в образ вручную (не сделано в этой
   итерации, см. `TECH_DEBT.md`).
3. **Эвристический классификатор — не AI**, а поиск ключевых слов/regex. Уверенность
   отражает грубое совпадение с шаблоном, не статистическую модель. Полноценная
   AI-классификация — по плану Итерация 4.
4. **Поля типа `link`** (например, «связанный загранпаспорт» у визы) в этой итерации —
   обычное текстовое поле для id записи, без поиска/автодополнения в интерфейсе.
5. Как и в Итерации 1, `prisma generate`/типы `@prisma/client` не проверялись живьём в
   песочнице агента (сетевое ограничение) — только вручную через `psql`. Backend
   компилируется без ошибок за вычетом этого известного разрыва.

## Что добавлено (второй проход — по результатам реального тестирования)

По результатам вашей проверки на реальных документах (паспорт, трудовой договор, военный билет, кассовый чек) и приложенного расширенного ТЗ тестирования доработано:

- **MRZ-парсер загранпаспорта** (ICAO 9303 TD3, с проверкой контрольных цифр) — приоритетный источник данных, надёжнее произвольного текста разворота.
- **Извлечение позиций кассового чека** (товары, количество, цена, сумма, ФН/ФД/ФП) — без обращения к ФНС, только эвристический разбор OCR-текста, как явно согласовано.
- **Field-level confidence** — уверенность распознавания теперь по каждому полю отдельно, не только по документу в целом; в форме подтверждения поля с низкой уверенностью помечаются предупреждением.
- **Защита от молчаливой перезаписи** — повторная загрузка/пересъёмка документа для уже существующей карточки не подставляет новые значения автоматически: система показывает «текущее vs предложенное» по каждому отличающемуся полю, пользователь выбирает явно.
- **Обнаружение дубликатов** — по контрольной сумме файла, с предупреждением и ссылкой на существующую запись.
- **Связь документа с несколькими людьми** (`EntityPersonLink`) — документ ребёнка может быть виден и в профиле родителя без дублирования объекта.
- **Автосвязи документов личности** одного человека (паспорт↔СНИЛС↔ИНН↔загранпаспорт↔ВНЖ↔ПМЖ↔водительское) создаются автоматически при подтверждении, если у человека уже есть другие документы личности.
- **Просмотр/скачивание прикреплённого файла** прямо на карточке документа.
- **Кнопка «Переснять/переобработать»** на карточке — запускает конвейер заново для существующей сущности.
- **Повторная попытка OCR** при ошибке обработки — без необходимости заново загружать файл.
- **Расширенный каталог типов**: военный билет, кассовый чек, тип-заглушка для неопределённых документов.
- **Реальный баг поиска исправлен** — раньше индексировалось только поле `content` (для базы знаний), теперь — все атрибуты любого типа. Добавлен разовый скрипт пересчёта для уже созданных документов.
- **Качество OCR** — предобработка изображений (`sharp`: авто-поворот, градации серого, автоконтраст, резкость, увеличение мелких фото) + режим Tesseract PSM 6.
- **Полностью офлайн-режим OCR** — языковые данные вшиты в Docker-образ на этапе сборки, растеризация сканов PDF через `poppler-utils` — без единого сетевого запроса в рантайме.

Полный перечень честно незакрытых пунктов (ФНС, AI-классификация, очередь фоновой обработки, MRZ для составных документов и т.д.) — в `docs/TECH_DEBT.md`, пункты 18–28.

## Что добавлено (третий проход — очередь, автосвязи, многостраничность, лимиты)

- **Очередь фоновой обработки OCR на Redis + BullMQ** — по выбору владельца системы (полноценный
  брокер, а не лёгкая версия на Postgres). Загрузка документа больше не блокирует HTTP-запрос:
  файл сразу встаёт в очередь (`status: PROCESSING`), воркер обрабатывает его асинхронно
  (concurrency=2). Поддержана пакетная загрузка нескольких файлов сразу — все встают в очередь
  мгновенно, интерфейс не виснет. Реально протестировано с настоящим Redis в среде разработки
  агента (не эмуляция) — очередь и воркер подтверждённо работают end-to-end.
- **Автосвязь врача/медицинской организации** для рецептов/заключений/посещений/вакцинаций —
  эвристический разбор подписанных полей бланка («Врач: …», «Учреждение: …») с сопоставлением
  уже существующих карточек в пространстве и автоматическим созданием `EntityLink`. Это НЕ NLP —
  полноценное распознавание участников в тексте без явных меток остаётся в Итерации 4.
- **Постраничная разметка составных документов** — сканы PDF хранят OCR-результат каждой
  страницы отдельно; на карточке паспорта РФ можно разметить конкретную страницу (регистрация,
  брак, дети) как отдельную дочернюю запись без повторного OCR.
- **Явный лимит размера файла (100 МБ)** с понятной ошибкой 413 вместо зависания/непонятного
  сбоя при очень больших файлах.
- **Скрипт нагрузочного тестирования** (`ops/load-test/document_upload_load_test.sh`) — честно:
  агент не может провести реальное нагрузочное тестирование на чужом сервере через сеть, поэтому
  вместо выдуманных цифр — рабочий скрипт для самостоятельного прогона на вашем ThinkPad.
