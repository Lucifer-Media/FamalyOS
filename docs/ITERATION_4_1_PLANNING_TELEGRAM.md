# Family OS — Итерация 4.1: финансовый план + Telegram-бот

## 1. Финансовый план (`/finance/planning`)

Задача: «сколько откладывать на врачей, отпуск и прочее с учётом всех
планов — личных и общих, и чтобы система подсказывала».

**Идеи из референсов**
- MoneyMatter (goals feasibility): свободные деньги в месяц = **медиана**
  (доходы − расходы) за 6 последних полных месяцев, минимум 3. Медиана, а
  не среднее: отпуск или премия в одном месяце не ломают картину. Цели
  финансируются по очереди, следующая «влезает», только если влезли
  предыдущие.
- Actual Budget (goal templates): резерв под регулярную трату — «20 000 ₽
  раз в 6 месяцев» превращается в ежемесячный взнос.

**Виды планов** (это та же `financial_goal`, пополнения — на «Копилках»):

| Вид | Пример | Сколько в месяц |
|---|---|---|
| Накопить к дате (`TARGET`) | Отпуск 180 000 ₽ к 20.12 | остаток ÷ месяцы до срока |
| Резерв под регулярную трату (`RECURRING`) | Стоматолог 20 000 ₽ раз в 6 мес. | max(сумма ÷ период; остаток ÷ месяцы до ближайшей даты) |
| Ежемесячный резерв (`OPEN`) | Врачи и лекарства 6 000 ₽/мес | как задано |

- **Личный / общий**: у плана есть «чей» (`scope` + владелец). Фильтр на
  странице: все / общие / личные / личные конкретного человека. Деньги —
  общий котёл семьи (без взаиморасчётов).
- **Порядок**: приоритет 1–5, при равном — ближайший срок. Что не влезает,
  показывается с новой датой «успеем к …».
- **Что если**: поле «А если свободно в месяц будет …» пересчитывает всё.
- **Прогноз по категориям**: среднее за 6 мес., тренд (последние 3 к
  предыдущим 3), прогноз = 60% последних 3 мес. + 40% всей истории. Для
  категорий вроде «Медицина/Аптека/Врачи/Авто/Подарки» без резерва — подсказка
  «предлагаю откладывать N ₽/мес», кнопка «завести резерв» создаёт план.
  Если резерв меньше факта — подсказка увеличить.
- **Таймлайн 12 месяцев**: когда наступают сроки и циклы резервов, хватит ли.
- **ИИ**: «Разобрать план с ИИ» и вопрос по плану. Цифры считает код
  (`finance-planning.ts`), модель только объясняет; числа в ответе
  проверяются — чужие помечаются.

История строится только из фактических операций в базовой валюте, без
переводов между своими счетами и без плановых операций.

## 2. Telegram-бот

### Что нужно на сервере

1. Токен бота — у @BotFather (`/mybots` → бот → API Token). **Только в
   `.env`, не в чат и не в git.**
2. В `.env` рядом с `docker-compose.yml`:
   ```bash
   TELEGRAM_BOT_TOKEN=123456:ABC...
   TELEGRAM_ALLOWED_CHAT_IDS=-5373163824     # можно несколько через запятую
   # TELEGRAM_API_URL=https://...            # только если api.telegram.org недоступен напрямую
   # TELEGRAM_BUDGET_CHECK_MINUTES=60
   # FAMILY_TIMEZONE=Europe/Moscow
   ```
3. Для группы: в @BotFather `/setprivacy` → бот → **Disable**. Иначе бот
   видит в группе только команды, и записывать придётся через `/r 350 кофе`.
4. `docker compose up -d --force-recreate api`. Бот работает через long
   polling: наружу ничего не открывается, нужен только исходящий доступ к
   `api.telegram.org`. Проверка: `docker compose exec api wget -qO- https://api.telegram.org`
   или страница «Финансы → Telegram» (статус и последняя ошибка связи).

### Привязка

Каждый член семьи: Family OS → Финансы → Telegram → «Получить код» → в чате
`/link 123456` (код одноразовый, 10 минут). Записи из бота сохраняются **от
имени этого пользователя** — с его правами, версиями записи и журналом.
Кнопками под записью может пользоваться только её автор. Отвязка —
`/unlink` или кнопка на странице (архив, без удаления).

Если Telegram превратит группу в супергруппу, ID чата сменится на `-100…` —
бот в незнакомом чате ответит новым ID (раз в час), его нужно вписать в
`TELEGRAM_ALLOWED_CHAT_IDS`.

### Запись трат

```
350 кофе                 такси 800 вчера        05.11 аптека 1200
1.5к стоматолог          +50000 зарплата        кино 900 личное
продукты 2000 семейный счёт альфа               кофе 300 основной
```
- Несколько строк — несколько операций.
- **Счёт** — по словам в сообщении: наименование счёта, банк (тиньк,
  тинькофф, тбанк, альфа, сбер, втб, озон…) и владелец. «семейный счёт альфа»
  и «семейный счёт тиньк» — разные счета; «основной» — основной счёт того,
  кто пишет; «основной арина» — счёт Арины. Если подходят несколько — бот
  спрашивает кнопками. Если в сообщении счёта нет — счёт по умолчанию
  (`/account`). Просто «семейный»/«личный» без «счёт» — это тип расхода.
- **Категория**: правила автокатегоризации → словарь магазинов/слов → ИИ (в
  фоне, сообщение обновится). Поправить — «📂 Категория».
- Кнопки: «👤 Сделать личным / 👪 семейным», «↩️ Отменить» (архив).
  Повторная доставка того же сообщения не задваивает запись.

### Команды

`/month` (`/month prev`), `/today`, `/budgets`, `/plans`, `/goals`, `/due`,
`/balance`, `/report` (ИИ-отчёт за прошлый месяц, пришлёт по готовности),
`/ask вопрос`, `/account`, `/undo`, `/help`, `/link`, `/unlink`.

### Уведомления о бюджете

Когда бюджет доходит до своего «Порога предупреждения, %» (по умолчанию 80%)
и когда превышает 100%, бот пишет в чаты привязок. Проверка — сразу после
записи через бота и раз в `TELEGRAM_BUDGET_CHECK_MINUTES` (импорт, ручной ввод).
По каждому уровню — один раз за период бюджета (запись
`telegram.budget_alert` в журнале — она же защита от повторов). Выключить:
флажок «Уведомлять о приближении к порогу» в бюджете или «бюджеты» в
привязке.

## 3. Счета

- **Наименование счёта** — новое поле, заголовок счёта везде (полужирным),
  по нему ориентируется бот. Под заголовком — банк.
- **Общий (семейный) счёт** — флажок. Разбивка на странице «Счета»: «Общие»
  (флажок или нет владельца) и «Личные · <участник>», с суммой по группе.
- **Транзакции**: «Показать архивные счета и операции» — по умолчанию
  архивные скрыты; в формах ввода только активные счета.

## База данных и права

Миграций нет: новые поля в реестре (`financial_goal`: planKind, scope,
recurrenceMonths, nextDate, plannedMonthly; `bank_account`: accountName,
isShared), новый тип `telegram_link`. Все действия бота — через
`EntitiesService` и финансовые сервисы (права FINANCE, версии, аудит).
Аудит: `telegram.transactions_created`, `telegram.budget_alert`,
`telegram.link_code_issued`, `finance.planning_ai`.

## Тесты

270/270 backend: `finance-planning.spec.ts` (движок плана),
`finance-planning.service.spec.ts` (сбор истории: переводы/плановые/валюта),
`telegram-parser.spec.ts` (разбор сообщений, категории по словам, пороги),
`telegram-bot.spec.ts` (белый список, привязка, запись от имени пользователя,
выбор счёта по наименованию/банку/владельцу, неоднозначность → кнопки,
дедупликация, отмена, чужие кнопки, уведомления о бюджете).

**Что агент проверить не может:** реальную связь с Telegram из этой
песочницы — бот проверен на фейковом клиенте. Первый живой тест — на сервере.
